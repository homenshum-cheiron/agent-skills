# The decisions behind the setup

This is a curated public set of reusable decisions, not a complete transcript and not a claim that every practice below is implemented. The methods are original public writing. Examples elsewhere in the repo are synthetic. Rows group related choices when they protect the same invariant. There is one decision log.

| Tempting shortcut | Decision | Why it matters | Where it lives |
|---|---|---|---|
| Start building while the behavior is still fuzzy | When background, behavior, interactions, change shape, or the expected interface is unclear, write the smallest useful direction packet first. This covers UI, API, data, agent, and incident work. Skip it for a short change that is already obvious. Pick cues that answer a named question. Use a mock for layout and state, and a functional prototype with synthetic fixtures only when a mock cannot explain the behavior. Never imitate a sign-in or collect credentials. Mermaid is enough for many flows. A picture is not runtime proof. | A little upfront writing avoids building the wrong thing, without adding an approval gate or a required platform | [Direction before work](../skills/direction-before-work/SKILL.md) |
| Start by naming services and agents | Start with an input, the expected output, one failure, the error contract, and side effects, including none. Read the current path at a named commit. Skip a later stage only when it does not apply, and say so. | A plan can be evaluated before implementation, and formatting is not a substitute for that plan | [Scenario first](../skills/scenario-first/SKILL.md) |
| Let the implementation define its own answer key | Freeze acceptance separately, then compare a baseline and a candidate. One successful example is a capability probe, not a bake-off. | Prevents a changed implementation from grading itself | [Proof before review](../skills/proof-before-review/SKILL.md) |
| Call a code read, a unit test, or green CI a full review | Name the target base, the merge-base, and the tip. Run the surface the claim needs and record the command and the observed output. Combined-stack evidence names the parent and the composition. A documentation-only change may mark live proof N/A with a reason and a SHA. Missing required proof is unproven or blocked, not N/A. | Plausible code and a lower-level pass do not prove the behavior that was claimed | [Proof before review](../skills/proof-before-review/SKILL.md) |
| Score a pull-request body as a silent 9/9, or as 6/9 with two N/A | Nine prompts are coverage. Report supported over applicable, and list N/A with reasons. The teaching case is 6/7 applicable, plus 2 N/A. Coverage is not a quality certification. | A reviewer who has not seen the work should be able to see what is present and what was skipped | [Proof before review](../skills/proof-before-review/SKILL.md) |
| Read APPROVED, a green check, or a merged pull request as done | A bot APPROVED state is not human approval. Honor a configured bot-owned gate as that gate. Follow the project's declared gates, including when a prior review still covers a non-semantic change. Disposition each actionable finding on the current tip. Successor lineage is a preserved SHA or patch content. Queued CI is not green. Candidate, reviewed, landed, deployed, and live-verified stay separate. | Each of those words is a different fact, and this repo does not invent a stricter universal review policy | [Proof before review](../skills/proof-before-review/SKILL.md) |
| Add another writer, or treat a handoff file as a lock | One writer owns a mutable branch. Verify what is already in use. Readers and independent branches may run in parallel. A handoff, a JSON field, or a flag is not fencing, authority transfer, spend enforcement, or a production lock. Auto-transfer requires compare-and-swap of head, epoch, fencing token, and owner, plus a verified stop. If those are missing, do not auto-transfer and do not claim the runtime is ready. A handoff does not widen send, review, merge, or spend permission. Borrowed planner or worker seats are temporary. | Two writers on one mutable branch overwrite each other, and a note cannot pretend to be a distributed lock | [One-writer handoff](../skills/one-writer-handoff/SKILL.md) |
| Use the strongest model, a cheap lane, or a fresh judge by default | Choose model and effort together from a fresh supported host and account read, shared capacity, reserves, the task, and the risk. There is no fixed planner, worker, boss, or cheap lane. Difficulty alone does not select the strongest model or add a reviewer. A name in a document is not a catalog claim. Fable at medium effort is one illustrative eligible profile when that host lists it, never a default or a role pin. A smaller listed model still needs clear inputs and a verifier. | Host catalogs and account capacity change, and a pinned lane goes stale | [Budget-aware routing](../skills/budget-aware-routing/SKILL.md) |
| Treat a CLI budget flag or a test plan as permission to spend | Verify when spending is checked, including the first request. Post-request accounting can exceed a nominal limit. Spend personal budget only when the owner asked. | A flag and a matrix are not a pre-request guarantee and not an approval | [Budget-aware routing](../skills/budget-aware-routing/SKILL.md) |
| Say "this is not a separate API bill" | Separate included subscription allocation, overage or hybrid dollars confirmed from a supported source, and list-price hypotheticals. Report the host, account class, model, effort, and the source that was read. A billed API path does not always mean the user supplied an API key. | The wrong class reports a hypothetical as a bill, or hides a real overage | [Subscription usage](../skills/subscription-usage/SKILL.md) |
| Choose from a feature list, or start a paid bake-off | Write non-negotiables first. Read public results before any new paid or self-run comparison. If an arm breaks the rules, every arm it touched is invalid. | Avoids buying the best brochure and avoids an unasked spend | [Criteria before choice](../skills/criteria-before-choice/SKILL.md) |
| Sum every span, or claim a speedup from a live process | Separate wall time, overlap, and unexplained gaps. Measure named scenarios into a before and after table, with accuracy on the same run, before claiming a speed or cost win. | Parallel work cannot be counted twice as user delay, and a missing table is not a win | [Measure the path](../skills/measure-the-path/SKILL.md) |
| Add a tool or a store because the list looks thin | Widen an existing tool with an optional parameter or a richer return. A new tool needs a written reason. Borrow an idea, not a whole framework. | New surfaces accumulate faster than they get used | [Lean tool context](../skills/lean-tool-context/SKILL.md) |
| Load the whole history into the prompt | Keep at most 16 working rows, and retrieve evicted detail from a durable handle. | The reasoner stays on the goal, and the detail remains findable | [Working set](../skills/working-set/SKILL.md) |
| Repair every failure in one loop, or leak internal health into the answer | Separate data-operation incidents from agent and evaluation failures. Define the exposure policy separately from detection. | Owners, remedies, and what a user may see are different | [Route failures](../skills/route-failures/SKILL.md) |
| Rewrite a recap from whatever is live, or delete a superseded finding | Review a bounded snapshot, then publish against the expected prior version. Keep rejected and superseded lines retrievable. Do not self-certify a promotion. | Prevents a stale review from overwriting new work, and prevents a refuted parent from disappearing | [Bounded publication](../skills/bounded-publication/SKILL.md) |
| Restate a correction only in chat | Append a dated ledger line, with source and trust, before continuing. Retrieval must be able to return the line it replaced. | The next session cannot see a correction that lives only in a transcript | [Encode corrections](../skills/encode-corrections/SKILL.md) |
| Trust a summary after a restart, or treat code as the requirement | Refresh a five-check record at handoff, contradiction, and completion. If an older plan comes back, the replacing decision comes back with it. | A chain of thought is not evidence that history was used | [Context check](../skills/context-check/SKILL.md) |
| Describe activity as completion, or send the update yourself | Report the outcome, label verified, unproven, or not started, and treat done as acceptance in use. Draft messages and stop. A declined send is final. | Readers can make the next decision, and an unsent draft stays unsent | [Outcome-first updates](../skills/outcome-first-updates/SKILL.md) |
| Follow a fixed multi-step ritual, including for people | Compose a few principles for the situation. Judgment includes work and also feelings and relationships. A longer private collection is not republished, because its provenance and republication rights were not cleared. | The procedure and the goal sometimes disagree, and an uncleared list stays private | [First principles](../skills/first-principles/SKILL.md) |
| Ship a long answer as one block | Use headings, a bold lead sentence, and isolated warnings without changing meaning or hiding uncertainty. Leave short replies alone. | A skimmer should still see the decision | [Scan long answers](../skills/scan-long-answers/SKILL.md) |
| Reach for a heavier method before naming the outcome | Start from the usable outcome and the evidence already in hand. Characterize a few candidates, including no change, by mechanism, fit, anti-fit, prerequisites, evidence limits, tradeoffs, composition, and a check that could reject the candidate. A feature firing is not an improved task. A plan does not authorize paid work, training, or deployment, and publishing the plan is not a product improvement. | The result is a better outcome or a rejected hypothesis, not a longer survey | [Match methods](../skills/match-methods/SKILL.md) |
| Draw a ladder from documentation to autonomy | Keep documentation, offline checks, task autonomy, repeated improvement, and meta-improvement as separate claims. Unknown is not zero and not a percentage. A required approval stays in the human-burden count and is not a capability failure. A prompt edit is not, by itself, a recursive improvement. | A diagram that looks reachable will be read as a result | [Evidence map](autonomy.md) |
| Store a missing duration as zero, or treat a verdict as permission | A trace field is measured, derived, judged, estimated, or missing. Missing is null. Overlapping spans are not wall time, and a child cost already inside a parent is not counted twice. Reports keep current evidence apart from desired direction. A chart matches its table. A hypothesis-only note has no numeric chart. A recommendation does not grant the next step. | Honest records stay usable by a person and by a checker, and they do not pretend an architecture sketch is a running system | [Measure the path](../skills/measure-the-path/SKILL.md) |
| Send the long version, reuse an old number, or count a subset | Match the format and length the audience already uses. Use plain words with brief background instead of internal labels. Give the full denominator and its split. Skip what the reader knows. Write "not verified" instead of a stale value. Say how a large sweep was done and its caveats. Attribute runs by who started them; untagged is unattributed. Root causes follow the evidence, not a fixed number of whys. | Each of these was a real correction from a reader, and each one changes the decision the reader makes | [Outcome-first updates](../skills/outcome-first-updates/SKILL.md) |
| Ask before running a vague request, cite a summary blog, write prose first, label an unsourced line "unverified", or say "no rule exists" | Infer the scope, run it, and then confirm, unless the run would be unusually expensive. Cite a secondary source only with "according to" wording, after a logged primary attempt with workarounds. Write claims with quotes first and build the prose from them. Find a source for an unsourced sentence, or drop it and say what was checked. Write "No rule found in:" with a nested, linked list of sources checked. | The reader can see what was checked, and a wrong answer traces back to the claim, source or step that failed | [Walk the document](../skills/walk-the-document/SKILL.md) |
| Write a report as one long stream, or restyle an old page without checking it | Pick one document shape by purpose (quick brief, research summary, comparison, comprehensive report). Keep the summary, decided versus proposed, detail, evidence versus illustration, owned open items, next steps and linked sources apart. Check an existing report read-only against its shape before editing or re-sharing it. | A reader finds the answer, the decision state and the sources without reading everything, and a stale summary is caught before it misleads | [Outcome-first updates](../skills/outcome-first-updates/SKILL.md) |

## Keep the layers separate

- **Skills** guide decisions. They are not authorization or enforcement.
- **Host configuration** provides tools, account access, and discovery. The setup kit is that layer. On 11 Nov 2026 the public commit `20c3c62f775e36560ab092e5b249b3da44a14fa6` in the canonical kit had parent `5fd2f7cc6ee9c80b890049dad8cd4e7937635532`, the personal public snapshot. The canonical commit message records long-running request records and revision-bound handoffs, and `docs/long-running-goals.md` is present at that pin. Those repositories are not modified here. The one-commit gap is a fact about those revisions, not a task to sync the fork. If a recipe here disagrees with an older kit default, follow the later dated decision in this file.
- **Execution infrastructure** owns real isolation, concurrency, quotas, and durable state.
- **Verification** evaluates an exact artifact and its stated scope.
- **Release decisions** remain explicit and separate from test results.

If a practice becomes friction without protecting a real invariant, simplify it. Do not replace a removed guard with an undocumented automatic action.
