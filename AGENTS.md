# Working on this collection

Keep each skill independently usable. All references inside a skill must stay inside its folder. Prefer one clear outcome to a growing checklist of every possible task.

Write original, public-safe examples. Do not add employer code, transcripts, customer material, secret values, private URLs, home-directory paths, live account identifiers, or permissions copied from another task. Synthetic examples must be labelled.

Preserve uncertainty: source inspection is not a test run; focused tests are not a full suite; an offline helper is not a running service. Run both commands in README after edits, and record what was actually tested. Do not claim semantic skill quality solely from structural validation.

Do not add automatic global installation, provider calls, model locks, permission changes, or background schedules. Keep scripts local and explicit. A workflow may recommend a check without imposing a new application CI gate.

Named models in a skill are illustrative. They are not an availability claim and not a default role pin.

Do not describe a lock, merge gate, budget meter, or router as if this repository enforces it.

Follow the destination project's declared review gates. Do not invent a stricter public rule.

Do not republish an uncleared private collection, including a longer personal list of principles. Examples stay synthetic.
