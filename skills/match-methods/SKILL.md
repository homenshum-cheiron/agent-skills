# Match methods

Aim at a better user outcome, or at a hypothesis you can reject. More documents, more experiments, or a higher proxy score are not that result.

Match the effort to the risk. A plan does not authorize paid work, training, deployment, or a permission change. Change the system only where that change is already authorized. Publishing this note or opening a pull request is neither authorization nor proof that a product improved. Free analysis can continue while paid work stays paused.

This is not a fixed sequence and it assigns no model role. Skip a block that does not apply, and say so.

## Outcome and evidence first

Write who needs what result, on what input; what happened instead and why it matters; the evidence already in hand (frozen case, answer, trace, sources, build and prompt versions, grading rules); and the gaps. Do not invent missing values. Survey widely only when the mechanism is uncertain. A demonstrated cause does not need another landscape pass.

## Profile, causes, falsifier

Name the stage and the contrast that would change the method: identifier versus paraphrase; the right document with the deciding passage nearby versus a demonstrated cross-document relation; precision versus recall; abstention versus a confident wrong answer. Record only binding constraints, such as freshness, authority, latency, spend, or residency. Tags help search. They are not a cause.

Internal causes include the tool, schema, what was loaded, prompts, rules, data, permissions, filters, and context assembly. External causes include a poor method, missed prior art, or the wrong metric. They can interact. Also keep nulls: thin telemetry, wrong gold, a bad judge, contamination, an environment failure, or ordinary variance. Follow the chain from parser output to worker input, verifier input, and the persisted result. Name the observation that would reject the leading candidate.

## Candidates, including no change

Keep current behavior. Add a method only when its mechanism fits this failure. Drop a hard-constraint or known anti-fit failure. A missing prerequisite is a separate costed proposal.

For each survivor record mechanism, fit, anti-fit, prerequisites, evidence and its transfer limit, tradeoffs, composition, and the cheapest rejecting check. Fields, extra candidates, and re-read public figures are in [the catalog](references/catalog.md). A citation is not proof a pipeline ran here. An unvalidated two-loop sketch is in [loops](references/loops.md). Honest report shapes are in [report formats](references/reports/README.md). A recommendation there is not permission.

Compare quality, latency, throughput, usage, and maintenance without inventing a rank. Combine methods only across stages, and watch interference. Prefer a lean design when heavier benefit is unevidenced. Say what would change the pick. Test competing causes separately. A unit cost needs an explicit denominator.

## Symptom measures

Use one usable-outcome measure, quality and authority guards, and only the diagnostics that separate the live hypotheses. A feature firing or a lower counter is not the outcome. The outcome is a valid supported task that improved without breaking those guards.

Label each figure measured, derived, judged, estimated, or missing. Missing first-token time is missing, not zero. Summed parallel work is not elapsed time. The delaying branch is the critical path. Recorded time bounds waste and does not guarantee savings. Allow a valid alternate path. Edit distance is not the only waste metric. Query-time reading is not index-time context or a graph. An installed catalog is not what was sent. A prompt-cache hit is not source freshness.

## Checks, grades, and boundaries

Prefer a schema check, a frozen export, a stub, or a replay. Replay cannot show a live model-policy change. A public comparison does not authorize a new self-run benchmark. When one is authorized, name the dated baseline, try one change on one case before combining changes, and diagnose a loss. The owner decides.

A human must be able to grade the same pack. Separate development, calibration, and held-out material. Builders do not tune on a sealed key. A fresh-context review, when needed, gets the pack rather than the persuasive draft. Fresh context is not independence, and a swarm is not required.

Before training a keep-or-drop decision, try a rule or a small bounded call. A routing model is not a router. Log a versioned id, not an alias. Training still needs labels, held-out results including shift, a floor, a safe fallback, a drift owner, and both error types. This skill authorizes no training run.

Agent-to-agent interop fits separate runtimes, not a shared account. Protocol completion is not product approval. Read the current spec for retry and cancel before shipping identity, consent, duplicate-work policy, hop limits, and partial-failure tests.

Report the problem, hypotheses, eliminations, allowed check, and state separately. After an authorized run, adopt, revise, reject, or stop, and say why. The [hypothetical examples](examples/worked.md) are not traces and not permission to build.
