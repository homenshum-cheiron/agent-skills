# Report shape and validation

Use this for a saved report, page or long write-up, not for a chat reply or a short status.

## Source and attribution

The four document shapes below follow Notion Labs' `research-documentation` skill in [makenotion/claude-code-notion-plugin](https://github.com/makenotion/claude-code-notion-plugin/tree/016c74ffc568920a385186fb9d2d9d2801e0be09/skills/notion/research-documentation), read at commit `016c74f` on 12 Nov 2026. Its `plugin.json` declares the MIT license; the repository had no separate license file at that commit. This page is an original summary. It does not copy the templates. Read them at the link.

## Pick one shape by purpose

- **Quick brief.** A direct answer or a status. A few sentences, key points, actions, a short source list.
- **Research summary.** The default. A short summary, three to five findings with their evidence, analysis, conclusions and next steps, sources.
- **Comparison.** What is compared, a matrix on shared criteria, pros and cons per option, a recommendation with its reason, sources.
- **Comprehensive report.** Summary, background, method, findings, evidence, implications, ranked recommendations, appendix.

Whatever the shape, keep these apart: the summary first; what is decided and what is only proposed (and who decides); the detail; evidence and sources apart from illustrative examples; open questions and placeholders with owners; next steps; grouped sources with links at the end. Leave out a section that would be empty or repeat another. There is no minimum length.

## Validate an existing report

Read it first and do not edit while checking. Mark each check pass, fail or not applicable, with the heading or line behind each fail.

0. Which shape fits its purpose? Judge the rest against that shape.
1. The shape's sections are present and in order.
2. The first screen states the answer, status or decision in plain words.
3. Decided and proposed items sit in separate, labelled places.
4. Measured or sourced facts are apart from illustrative examples, and illustrative values are labelled.
5. Material claims cite their source next to the text.
6. A grouped source list exists with links a reader can open. Local file paths alone fail.
7. Each placeholder or open question names an owner.
8. Next steps name an owner or a done-when.
9. Terms, acronyms and code names are explained on first use or linked.
10. The page says when it was last checked, and later updates are reflected in the summary. A summary contradicted by an appended log fails.

Report a table of check, result and reason, then the top three fixes in priority order. Fix only when you are allowed to edit; otherwise hand the list to the owner.
