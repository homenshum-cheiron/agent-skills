# Example: a temporary split and a soft budget (synthetic)

Task: update an API and its documentation. For this task, one seat freezes the response contract, one seat owns the implementation, and one seat writes the docs against that contract. A reviewer checks the actual behavior after integration. The split is a temporary arrangement for the task. It is not a standing planner, worker, or boss lane, and it does not assign a model.

The first planner request has a nominal $0.10 budget but includes a large tool/system payload. If the host checks cost only after the response, it may exceed the nominal budget before refusing another call.

Safe plan: inspect limit semantics and request size before a paid probe; do not promise a hard cap without enforcement evidence. An offline JSON handoff that parses successfully proves the format, not live routing, quota isolation, or completion.

Synthetic selection note, not a live catalog read: if a fresh supported listing includes Fable and medium effort, that pair is an eligible profile for freezing the contract, because the task is mid-sized and a usage reserve remains. It is not chosen because this skill pins it. A design review does not automatically add the strongest model and a new judge. The docs seat can use a smaller listed model once the contract and the verifier are frozen. If the host listing omits Fable, the note says so and names the profile that was actually listed. No paid bake-off starts unless the owner asks.
