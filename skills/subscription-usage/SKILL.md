# Subscription usage

Name the billing path you actually checked. "It is not a separate API bill" is sometimes false. Accounts can have included allocation, overage, hybrid billing, or a billed API path.

1. Identify the configured path from a supported source: an official usage or billing surface, host documentation, or the account's stated plan. If you cannot check, say so.
2. Keep these classes separate:
   - **Included subscription allocation** — usage drawn against an included quota, as that source shows it.
   - **Overage or hybrid dollars confirmed** — extra charges only when the same class of supported source shows them.
   - **List-price hypothetical** — a what-if at public list prices. Label it hypothetical. It is not an actual bill.
3. A billed API path does not always mean the user supplied an API key. Host-billed and provider-billed paths exist. Check the path in front of you.
4. Write "this is not a separate API bill" only when the configured path and the overage facts support that sentence.
5. Spend personal budget only when the owner asked. A skill, a plan, or a matrix does not create permission.
6. When you report a run, include the host, a generic account class, the model, the effort, and which source you read.

An unsupported guess is unproven. This skill does not start a paid run or open a billing change.
