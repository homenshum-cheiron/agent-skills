# Criteria before choice

Set the elimination criteria before reading the winning product's feature list.

1. Write non-negotiables, useful preferences, and the actual scenario. Include data handling, platform compatibility, licensing, and total cost when material.
2. Keep eliminated candidates in the comparison. Mark each criterion pass, fail, or unverified, with a dated source or observation. Marketing statements are claims, not integration tests.
3. Before any new benchmark or paid comparison, read current public reviews and published results. Cite the revision or access date. If they answer the decision, stop. A private run for completeness is not required. If a new comparison is still required, write the smallest plan and wait for the owner to ask before spending. Writing the plan is not approval. If a pilot breaks its own rules, every arm it touched is invalid.
4. Resolve the decisive unknown with the cheapest authorized experiment. Do not spend time scoring cosmetic preferences for an option that fails a required constraint.
5. Compare survivors on the same input and accepted outcome. Account for adapters, operations, and migration, not just request price. One successful example is a capability probe, not a bake-off.
6. Run a premise check before recommending anything, including a finding or a research item: (a) real volume in the project's own units, with a source; (b) the saving or cost per year against the trusted baseline; (c) which direction the risk runs, meaning where the benefit actually comes from; (d) the expected harm or gain in real units. Show the arithmetic and label each assumption observed, derived, or estimated. If the saving is small next to the harm, or the arithmetic does not add up, name the missing variables (open pull requests, product direction, demand, headcount, compliance and validation) and downgrade or drop the option. See [the premise check](references/premise-check.md).
7. State the recommendation, the trade-off, the remaining uncertainty, and the trigger for revisiting it.

Use [the comparison example](examples/worked.md) and [the plan notes](references/comparison-plan.md). Avoid universal model rankings: availability and capability change. This skill does not authorize spend.
