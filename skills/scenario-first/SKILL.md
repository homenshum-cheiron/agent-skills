# Scenario first

Before dividing work, make the desired result falsifiable.

1. Write the actor, starting state, input/action, expected observable output, and one important failure. Do not replace a missing product decision with an implementation guess.
2. Identify the source of the expectation. A specification, accepted example, or domain reviewer is stronger than an answer generated by the candidate itself. Mark disputed expectations as decisions, not defects.
3. Find the smallest existing path that can exercise the scenario. Inspect tools and code before inventing services or a new orchestration layer.
4. Draw dependencies by artifact: which task needs which contract, schema, or tested output? Parallelize independent tasks; reserve one writer per shared artifact.
5. Choose a cheap verification ladder. Use fixtures before network calls, sample ingestion before bulk work, and real end-to-end checks only when prerequisites and permission exist. A lower rung does not establish a higher one.

Deliver a short work map: scenario, expected result, owner, dependency, check, current evidence, and unresolved decision. Scale detail to risk.
