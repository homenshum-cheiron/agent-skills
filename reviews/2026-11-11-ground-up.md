# Ground-up review: deterministic pass and prepared model trials

Scope: public revision `eb7ddc302fc4fcc120deef2fab4067b1340e4fc4` plus the local review candidate. This is an executable local review, not a completed Fable review or model-effectiveness experiment.

## Reproduced finding

**Malformed integer crashes proof checker (local fix).** On Python 3.14.7 and 3.15.2, give the proof checker a JSON object whose `schema_version` is a 5,000-digit integer. Expected: structured `invalid` output and exit 3. Observed on the published revision: uncaught `ValueError`, traceback, and exit 1. The interpreter rejects conversion beyond its configured integer-digit limit before packet validation begins. Catching decoder `ValueError` preserves the intended invalid-input contract without weakening the integer limit. The new regression fails before the change and passes after it.

## Observed checks

- The original 32 tests passed independently.
- The initial expanded 36-test run passed on system Python 3.9.6. That runtime is below the README's stated Python 3.10+ support; it did not exercise the modern integer conversion limit.
- The expanded run on Python 3.15.2 reproduced the bug: 35 passed and one failed before the fix. A focused repeat on Python 3.14.7 also reproduced it.
- Five added deterministic test methods cover 250 random integer-interval cases against an independent occupied-cell oracle; 50 affine transformations; excessive JSON integer handling; a deeply nested top-level JSON list; and a ten-value malformed top-level shape grid. The nested-list test is not evidence of decoder recursion-limit handling: the tested modern runtimes decode it, then reject its top-level shape.
- After the one-line fix, all 37 test methods pass on Python 3.15.2. Structure validation finds ten skills and zero issues.
- Counts of generated cases are not independent model trials. The [verification receipt](2026-11-11-local-receipt.json) records the bounded outcomes.
